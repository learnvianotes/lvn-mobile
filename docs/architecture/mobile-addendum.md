# lvn-mobile addendum

How the Expo app implements section 13 of the spec (lvn-backend `docs/architecture/lvn-architecture-v2.md`). Where
this file and the spec disagree, the spec wins unless an accepted ADR says otherwise.

| Expo | SDK 52+ with dev client, EAS Build/Update | SDK 57 (current stable; 58 was 9 days old), **built locally without an Expo account** — prebuild + Gradle/Xcode (ADR-0008). `expo-dev-client` is added with the first native module in Phase 1 |

All three install side by side, each with its own scheme so a sign-in redirect opens the install that started it. Per-machine overrides go in `env/<variant>.local.env` (git-ignored). An unknown
variant stops the scripts and the app config. No OTA updates for now (ADR-0008).

## Building (no Expo account)

| Goal | Command | Needs |
| --- | --- | --- |
| Run on a phone or emulator with live reload | `pnpm android` / `pnpm ios` | Android SDK + JDK 17+; Xcode on macOS for iOS |
| Standalone Android APK | `pnpm build:android <variant> [--abi arm64-v8a]` → `dist/LearnViaNotes-<variant>-<version>.apk` | Android SDK + JDK 17+ |
| Install it | `adb install -r dist/<file>.apk` | USB or Wi-Fi debugging |
| iOS release on your own device | `node scripts/with-variant.mjs <variant> npx expo run:ios --configuration Release --device` | macOS, Xcode, an Apple ID |

`android/` and `ios/` are generated by `expo prebuild` and git-ignored — change native behaviour through
`app.config.ts` and config plugins only. Release APKs are signed with the debug keystore until a store upload key is
set up (installable on phones, not accepted by Google Play). CI builds the sandbox APK on every push to `main`.

If a build fails with `ninja: error: … libworklets.so … missing and no known rule to make it` (or a similar missing
native library), native build caches from an older dependency set are stale: delete `node_modules/*/android/.cxx` and
`node_modules/*/android/build`, then build again.

Measured 2026-10-08 on the dev machine: first `build:android development --abi arm64-v8a` 2 min 53 s (Gradle 9.3.1,
JDK 21), APK 42 MB, label "LearnViaNotes Dev", target SDK 36.

## Sign-in (§7.1, Phase 1)

- **Session.** `lib/auth/session.ts` keeps the access token in memory and both tokens in expo-secure-store
  (`lib/auth/storage.ts`; Keychain / Android Keystore, excluded from backups by the expo-secure-store plugin). Every
  request carries `X-LVN-Client: mobile`, so the API returns the refresh token in the payload instead of a cookie.
  The access token is renewed a minute before it expires; one refresh at a time (the API treats a reused refresh token
  as theft). On launch the stored refresh token is exchanged while the splash stays up; offline, the person stays
  signed in and the next request tries again; only the API's refusal signs them out.
- **Requests.** `lib/apollo.ts` retries once after a refresh when the API answers `UNAUTHENTICATED`. Operations live in
  `graphql/operations/*.graphql`; `pnpm graphql:sync && pnpm codegen` regenerates `graphql/generated` from lvn-backend's
  schema (a sibling checkout until `@lvn/contracts` is published).
- **Google (ADR-0007) — the sign-in shown at launch.** Native Google Sign-In
  (`@react-native-google-signin/google-signin`) picks the account and returns a Google ID token; Firebase
  (`signInWithCredential`, in-memory only) turns it into the Firebase ID token the API's `signInWithGoogle` accepts;
  both are signed out straight after (`lib/auth/google.ts`). The button shows when the API offers Google and the build
  has `EXPO_PUBLIC_FIREBASE_*` and `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`. Setup, once per Firebase project:
  1. Authentication → Sign-in method → enable **Google**. Its "Web SDK configuration" shows the **Web client ID** →
     `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` (the audience of the token Firebase accepts).
  2. Project settings → add an **Android app** for each variant (`com.learnvianotes.dev`, `.sandbox`, `com.learnvianotes`)
     with the **SHA-1** of the key the APK is signed with — that creates the Android OAuth client Google matches by
     package and key. Local release builds are signed with `android/app/debug.keystore`:
     `keytool -list -v -keystore android/app/debug.keystore -alias androiddebugkey -storepass android -keypass android`.
     No `google-services.json` is needed.
  3. Project settings → the **web app's** config → `EXPO_PUBLIC_FIREBASE_API_KEY`, `…_AUTH_DOMAIN`, `…_PROJECT_ID`,
     `…_APP_ID`; the API gets `FIREBASE_PROJECT_ID`.
  4. iOS (later, needs a Mac): an iOS app → `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`; `app.config.ts` then adds the URL scheme.
- **GitHub — kept for later.** Authorization Code + PKCE in the system auth browser (expo-auth-session), redirect
  `<scheme>://oauth/callback`, exchanged by `oauthExchange`. Not configured at launch; when it is, register that URI
  with the GitHub OAuth app and add it to the API's `OAUTH_REDIRECT_URIS`. `app/+native-intent.ts` keeps the router
  from treating the redirect as a screen.
- **LinkedIn — later, web first.** LinkedIn redirects only to http(s) URLs, never to an app scheme, so the app has no
  LinkedIn button. It needs Android App Links / iOS universal links for `https://<web>/oauth/callback`, or a page on
  lvn-web that hands the code to the app's scheme.
- **Emailed links.** Email confirmation and password reset links open lvn-web (`/verify?token=`, `/reset?token=`)
  until app links exist; the app asks for the reset link and the web page sets the new password.
- **Forms.** Date of birth is three number fields (day, month, year — GOV.UK's pattern for a date people know, not a
  picker). Emails are trimmed (keyboards add a trailing space). A wrong code or password is cleared for a fresh try.
  The API's `userErrors` land on their fields; anything else shows above the form.

Tests live in `tests/`, never in `app/`: Expo Router turns every file in `app/` into a route, so a test there
would be bundled into the app. `tests/unit` covers `lib/`, `tests/components` every exported component with props
(§17), `tests/e2e` the Maestro flows, and `tests/support` the Jest setup, mocks and `renderInApp` (the providers of
`app/_layout.tsx`).

E2E runs locally on an emulator with no cloud service: `pnpm test:e2e [variant]` (scripts/e2e-android.mjs) boots the
`lvn_pixel_7` AVD if none is running, installs the newest x86_64 APK of the variant from `dist/` and runs every flow
with `APP_ID` set to the variant's application id. The flows run against the real API of the variant (`API_URL`):
start lvn-backend's dev services and API first. `tests/e2e/scripts/create-account.js` makes a fresh account per flow
through the API, and `auth.yaml` reads the emailed code from Mailpit (`MAILPIT_URL`, default `http://localhost:58025`). Maestro's adb client lists no devices at all while any device is
offline, so the script stops and names offline devices first.

## Error reporting

`lib/observability.ts` starts Sentry (`@sentry/react-native`, the version Expo SDK 57 pins) first thing in
`app/_layout.tsx` when `EXPO_PUBLIC_SENTRY_DSN` is set: native crashes and unexpected JS errors only — no tracing,
screenshots or view hierarchy — without the user, request details, console output or query strings (sign-in redirects
carry codes). Autolinking adds the native module; the Sentry Expo config plugin is not used, because its Gradle step
uploads source maps and needs an auth token. Symbolicated stack traces (source maps, ProGuard mappings) are added with
the plugin when the Sentry project and its token exist.

## Brand assets

The logo is one set of shapes in `assets/brand/logo-paths.json`. `node scripts/brand-assets.mjs` (needs `rsvg-convert`)
renders the SVG sources in `assets/brand/` and every PNG Expo uses — app icon, Android adaptive foreground, background
and monochrome (themed) layers, splash and favicon — and `components/brand/Logo.tsx` draws the same shapes in the app.
The splash is the logo tile on the theme background (light `#F7F7FB`, dark `#0E0E12`) and fades out in ~220 ms once the
first frame is laid out.

## Folder plan (§3)

(`pnpm.auditConfig.ignoreGhsas`) because they sit in Expo's build tooling, never reach the app bundle, and have no
patched release:

| GHSA-86w9-cpqp-85rv (high) | node-forge | `expo › @expo/cli` | CLI only; no fix published |
| GHSA-vfj7-8cjw-p6xm (high) | braces | `expo › @expo/metro › … › micromatch` | Bundler only; no fix published |

Moderate, not ignored, tracked for the next SDK upgrade: `decode-uri-component` 0.2.2 via `expo-router › query-string`
(runtime; the fix, 0.5.0, is ESM-only and breaks query-string 7), `uuid` via `@expo/config-plugins › xcode` (build
time), `sprintf-js` via jest (test only). Remove ignores as soon as Expo ships fixed versions — Dependabot will open
the PR.
